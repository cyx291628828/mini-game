# 配置表说明（人工可编辑）

> 你直接用 Excel / WPS / 文本编辑器改这三张 CSV 表，改完提交即可，游戏加载时自动读取并校验。

## 三张表的分工

| 文件 | 管什么 | 谁在用 |
|---|---|---|
| `难度奖励表.csv` | **玩法类型 × 难度 → 奖励**（金币、碎片、骰子、首通加成、失败安慰金）+ 每档难度的谜题规格 | 结算系统 |
| `章节N-轨道表.csv` | 每章轨道上**每个节点是什么**（格子类型 / 玩法类型 / 事件） | MetaEngine 构建棋盘 |
| `全局参数表.csv` | 骰子经济、碎片保底、反弹开关等**全局数值开关** | MetaEngine / 经济系统 |

数据流：人工编辑 CSV → 提交仓库 → 预览/构建时打包进游戏资源 → MetaEngine 启动加载 + 校验（缺列、非法枚举、行数不符会在控制台报错并给出行号）。

## 表1：难度奖励表（字段字典）

| 列 | 说明 | 合法值 |
|---|---|---|
| 玩法类型 | 数独 / 扫雷 / 数方 / 星之战 / 杀手数独 | 枚举，勿改名 |
| 难度 | 简单 / 中等 / 困难 / 专家 | 枚举，勿改名 |
| 规格说明 | 该档难度的谜题规格（给人看的说明，程序按规格生成谜题） | 文本 |
| 金币 | 通关基础金币 | ≥0 整数 |
| 拼图碎片必得 | 通关**保底**碎片数 | ≥0 整数 |
| 额外碎片掉率% | 在必得之上，额外掉 1 片的概率 | 0–100 |
| 骰子 | 通关额外送骰子 | ≥0 整数 |
| 首通加成金币 | **首次点亮**该节点时的额外金币（叠加在金币列上） | ≥0 整数 |
| 失败安慰金币 | 失败时发放，不掉碎片、不计通关 | ≥0 整数 |

**结算公式（代码按此实现）**
- 通关：`金币 = 金币 + (首通 ? 首通加成金币 : 0)`；`碎片 = 必得 + (随机 < 掉率% ? 1 : 0)`；`骰子 = 骰子列`
- 首通点亮：额外**必掉 1 片缺片**（受全局参数「首通点亮必掉碎片」开关控制）
- 失败：原地不动，只发「失败安慰金币」
- 碎片保底：连续 N 次结算无新碎片 → 下次必掉缺片（N = 全局参数「碎片保底阈值」）
- 拼图集齐后：所有碎片掉落自动转为金币（1 片 = 20 金币，待定）

## 表2：章节轨道表（字段字典）

| 列 | 说明 | 合法值 |
|---|---|---|
| 节点序号 | 1 起连续编号，**必须从 1 开始且不间断**，行数须与全局参数「章节N轨道格数」一致 | 整数 |
| 格子类型 | 起点格 / 玩法格 / 金币格 / 骰子格 / 事件格（已按定稿移除 Boss 格、顶点格） | 枚举 |
| 玩法类型 | 仅玩法格填写 | 同表1枚举 |
| 参数/事件 | 骰子格：`+1`；事件格：`幸运转盘` / `下格奖励双倍` / `传送 -2～+3` | 见枚举 |
| 备注 | 给人看，程序不读 | 任意 |

轨道规则（代码固定，不在表里配）：起点与轨道末端是**边界**——锁定态越界反弹回走，解锁态越过末端进入下一章。

## 表3：全局参数表

`参数名,值,说明` 三列。参数名是程序引用的键，**勿改名**；值均为整数或 0/1 开关。当前参数：每日免费骰子、视频补骰子（数量/每日上限）、碎片视频加速次数、碎片保底阈值、首通必掉碎片开关、金币格金额、起点经过补给、解锁态后退转前进、锁定态两端反弹、首发章节数、各章轨道格数、各章拼图片数。

## 编辑注意

1. CSV 为 UTF-8 编码；Excel 直接打开若乱码，用「数据 → 从文本/CSV 导入」选 UTF-8。
2. **勿改表头文字与枚举值**（程序按名字匹配）；勿合并单元格。
3. 新增章节 = 复制 `章节1-轨道表.csv` 改名为 `章节2-轨道表.csv` 并编辑，再在全局参数表登记格数与拼图片数。
4. 新增玩法 = 先在难度奖励表加 4 行（四档难度），再在轨道表里使用。
5. 改完在预览里跑一圈棋盘，控制台无配置报错即生效。
